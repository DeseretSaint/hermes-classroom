# CP-042 — shipped pack evidence

Card: CP-042, branch `wt/cp-042-pack-shipping`. Owner `cbqa`, reviewer `atlas`.

Ruling applied (owner, 2026-11-10): the three packs under `bundled/packs/` are real store
courses a user adds to a library from Discover. Nothing a user can read — catalogue copy, manifest
metadata **or the lesson prose served from the pack's own section files** — is labelled demo,
sample or fixture, and each pack declares a redistribution licence.

## Why the gate now scans content, not only metadata

Pack section files are served verbatim: `coursebook/pack_flow.py` writes each
`objective.sections[].path` into `lesson_segments.kind='teaching'`, so a section that calls the
course a demo is exactly what the learner reads. At `e6a5807` the metadata gate was green while
two shipped courses still said:

```
technical-pack-literacy       content/section-01-anatomy.md:22    "A demo fixture can honestly say …"
technical-pack-literacy       content/section-02-labels.md:11     "This build's bundled fixtures do not carry it."
technical-pack-literacy       content/section-02-labels.md:17     "It is the honest default for a fixture …"
technical-pack-literacy       content/source-notes.md:3           "This technical demo teaches …"
japanese-affection-context-l0 content/section-01-two-ways.md:3    "This is a demonstration lesson …"
japanese-affection-context-l0 content/section-02-choosing.md:32   "… no native-speaker review is recorded for this demo pack."
japanese-affection-context-l0 content/source-notes.md:58          "… a schematic generated for this demo. The pack's own license is left `unspecified` …"
```

`tests/test_pack_shipping_labels.PackContentShippingTests` now reads **every declared text file**
in its staged bytes (mime `text/*` or a `.md`/`.txt` path) and fails on `/demo|sample|fixture/i`,
with a coverage assertion so a prose role cannot be skipped silently. Reproduction of the RED
state: a detached worktree at `e6a5807` carrying only this new test file gives

```
$ python3 -m unittest tests.test_pack_shipping_labels.PackContentShippingTests

```

and the same two tests are green on this branch.

## Covers: deterministic, text-free art (operator note, 2026-11-10)

The operator's live capture showed the Home shelf rendering `Auto Repir Fundamentas` and `Asttomamy`
— titles baked into model-generated cover art. A cover is therefore no longer model output: every
bundled cover is printed by `bundled/packs/build_bundled_packs.py::deterministic_cover` from flat
geometry (the same generator family as `relationship-map.png`), carries no glyph, and is released
`CC0-1.0`. The course title is DOM text on the card.

Two checks hold that rule in `tests/test_pack_shipping_labels.py::CoverArtTests`:

- the committed bytes must equal the generator's output (`deterministic_cover(kind)` and its
  portrait crop), so a hand-placed model image cannot pass;
- `tesseract` OCR over each shipped cover must find no alphanumeric character (6 files). The engine
  is present on this host, so the check ran rather than skipping.

No image toolchain is required: the covers are written deterministically by the plugin's own PNG
writer, so the SVGO/Sharp/pngquant line in `docs/design/TOOLCHAIN-50.md` is stale for this pack set
and nothing was installed.

9411) plus a live backend URL and bearer token. In this worker session no CDP listener existed on
9411 (or 9222/44311); the only Hermes Desktop process is the operator's own app, started without
`--remote-debugging-port`. The script was not pointed at the operator's live app and no frame is
claimed. The install proof above is backend JSON, not a screenshot.
