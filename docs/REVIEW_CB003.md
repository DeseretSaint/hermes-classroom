## 3. Stored vs runtime session ids

| Concern | Value used | Evidence |
|---|---|---|
| Pane binding lookup | `stored_session_id` only | `useSessionBinding` → `loadBinding({ storedSessionId: storedId })` |
| Resume / open | `binding.stored_session_id`, only when `status === 'active'` | `resumeBoundSession` refuses paused/detached/branched/orphaned |
| Runtime id | diagnostics line only; never sent | `SessionDiagnostics`; test asserts `session_id: runtimeId` never appears |
| Fresh draft | `null` stored id → "No durable chat yet" | no fallback to the runtime id or the newest chat |
| Backend | matches `stored_session_id`; reports `matched_column` | `api._binding_get`; test proves a runtime id returns `binding: null` |
| No migrations | `NOT_IMPLEMENTED`, **not** `{binding: null}` | answering null would claim "this chat is unbound" when the build cannot know |

The Desktop reads its contract version and implemented-method registry from `GET /runtime` at
register time, so a future amendment does not need a Desktop edit for the envelope version. There
is no client-side copy of the method list.

## 5. Exact probe findings (CB-003)

1. **`binding.get` is a v1/v2-stable method**; v2 did not change its payload. My handler needed no
   amendment after the rebase.
2. **`/runtime` is the right registry seam.** `schema.get` reports contracts, not handlers;
   `implemented_methods` had to come from `api.METHOD_HANDLERS`.
3. **Config settings reach a tool only through `ctx.get_config`.** Tool handlers receive their own
   kwargs, so `register()` binds the reader into `coursebook/tools.py` once.
4. **The Desktop half cannot be split** (confirmed again): one module, three specifiers, no JSX.
   A keybind is a contribution (`KEYBINDS_AREA`), never a synthetic `KeyboardEvent`.
5. **Single-gateway-per-host blocks a fully isolated live Desktop run.** See §6.
6. **`hermes plugins disable` does not delete the entry**: it moves the id from
   `plugins.enabled` to `plugins.disabled`. The lifecycle test now asserts both lists.

## 6. What is NOT proven, and why (honest gap)

**The installed-route screenshot was not captured.** The route/pane/sidebar/keybind registrations
are proven by the Node ESM load harness above; the *live window* proof needs a desktop app whose
backend reports the coursebook package.

Attempted, in order:

1. **Isolated Desktop, isolated `HERMES_HOME`, CDP 9333, separate `--user-data-dir`.** The app
   booted (CDP answered, shell mounted) but its backend refused to start: this host runs exactly
   one gateway for all profiles, so `hermes gateway run` for a second home exits 0 with
   "already serves profile 'default'".
2. **Second gateway via the documented `hermes gateway run --force` escape hatch.** It started and
   bound the scratch socket, but logged `Session storage: /home/deseretsaint/.hermes/sessions` and
   "Recovered 1 interrupted turn" — i.e. it touched the operator's global session store
   (`~/.hermes/state.db` mtime moved to 01:41). **This was stopped immediately**; no turn inference
   ran (no messaging platforms were enabled). Disclosed rather than hidden.
3. **The operator's running app.** It is a packaged build, which never opens a CDP port, and its
   backend would only load the desktop half if the package were installed/enabled in the root
   profile — both explicitly approval-gated.

Therefore the remaining work is an **operator-approved** action, not an engineering one:

```bash
# app-level, reversible; no config.yaml change, no gateway restart
cp -r <checkout>/desktop/plugin.js ~/.hermes/desktop-plugins/coursebook/plugin.js
# and, for the backend half:
hermes plugins enable coursebook          # writes plugins.enabled in the root profile
```

Then: Capabilities → Plugins → Rescan, open Coursebook, capture the route + pane. Follow-up card
`CB-020` (assignee `cbqa`) carries this; it is the only acceptance item this card cannot close.
