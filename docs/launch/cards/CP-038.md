# [CP-038] Capture door: addressable destinations, click and scroll hooks

Commit small, run what the card names, then `hermes kanban request-review <id> --reviewer <name> --summary "branch; commits; evidence paths; gaps"`. Never complete your own card.

Owner `sentinel`, reviewer `atlas`, 45m, worktree branch `wt/cp-038-capture-door`. This unblocks live evidence for every v3 screen card.

Defect, reproduced by CP-021: `scripts/cp-capture.mjs` hard-reloads and only then sets `#/coursebook`, so the route resets to Home; and no non-Home destination is reachable at all. CP-021's implementation is green at `f195f95` but it cannot photograph Workshop, so it is blocked.

Do:
1. Make routing survive the reload: set the hash before load, or wait for the plugin's route signal after setting it (`[data-cb-v3-ready]` plus a route attribute), and fail loudly if the requested route is not the rendered one — never silently save a Home frame under a Workshop name.
2. Add `--destination <route>` (e.g. `#/workshop`, `#/course/<id>`, `#/learn/<id>`), `--click <selector>` (repeatable, for click-through states like a selected line or an opened check card) and `--scroll <selector|px>` (for below-fold evidence).
3. Echo the resolved route into the stamp JSON (`route`, `destination`, `clicks`, `scroll`) so a still can never lie about where it came from.
4. Add `tests/test_cp_capture_route.py` (or extend the existing rig self-test) that asserts: home still works; a non-Home destination renders that route; a wrong destination exits non-zero and writes no file.

Done when: a real capture of Workshop and one of Course home succeeds on the current master build, the stamp carries the route, the wrong-destination case fails cleanly, and the home capture is unchanged.
