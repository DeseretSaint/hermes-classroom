## 2. Precomputed and live — the on-screen marks

Two segments are generated before recording, because doing them live burns the ceiling:

1. **Plan and research (13–25 s).** Generated by the same build, through the same backend path, then
   replayed on camera. On-screen caption for the whole segment: `generation recorded earlier in this
   build`. The narration says "both are on the record before any lesson exists" and never "generating
   now".
2. **Lesson media, if a media beat is added back.** Media is a cached artifact of the same build and
   is presented as a reopen, never as generation. Caption: `cached artifact from this build`.

Everything else is claimed live. A cut is allowed only to hide waiting (the restart), and the cut is
labelled for its duration. A judge must be able to tell which seconds were generated earlier from the
video alone, without reading the description.

## 3. Why no segment is captured yet (measured, not guessed)

Two independent blockers, both reproduced on 2026-11-08:

1. **Gateway binding.** This host runs one gateway, owned by profile `default`, and a second is
   refused. A window on an isolated home shows *Backend: checking* for every route and no chat
   composer for any hash, so segments 1, 2 and 4–10 have no driveable surface
   (`docs/REVIEW_CB017-FINAL.md` §3.1; CB-QA-09, reclassified P3-operational by Atlas).
2. **The clean seed has no materialized check.** The one labelled Sample classroom in a clean home
   (`~/.hermes/coursebook-test-h186`) holds 4 objectives and 4 lesson runs but **0 rows in `checks`**,
   so no attempt can be submitted and no evidence row can appear. Measured:
   `sqlite3 <home>/plugin-data/coursebook/data.db "select count(*) from checks"` → `0`.
   Until pack import materializes a check, the ledger beat (segments 5–9) cannot be shot at all.

A third, smaller fact: the demo profile that *does* render (`~/.hermes/coursebook-test`) is polluted
with debug rows — `H103 live reject check`, `H103 live failure check`,
`Parent demo: measuring ingredients together`, and three courses titled `…— an L0 demonstration
classroom`. Those rows cannot appear in a contest video. The exact inventory and the reset gap are in
`docs/STORY-GAPS.md`.

## 4. Cut list, in order, if the take runs long

Cut 6 (hint downgrade, −6 s), then 3 (plan, −12 s) if the take is over 90 s and the plan beat is
already visible in a still. Never cut 8 (the one-transition row), 9 (resume) or 10 (export): those
three are the product's only non-interchangeable claims.

## 5. Narration discipline

- Say "generated earlier in this build" wherever the precomputed caption is on screen.
- Never say "#1", "2 sigma", "guaranteed mastery", "proven to improve learning", "COPPA compliant" or
  "child safe". None of those is true of this product, and `docs/SUBMISSION.md` §0 is closed.
- Describe the mechanism, not the outcome: transition, evidence, approval, withhold, hash.
- One sentence per segment; keep each under about four seconds of speech.

## 6. The one operator action

Install the recorded commit into the gateway-owning profile and restart that gateway
(`scripts/install-local.sh --home ~/.hermes/profiles/default`, then `hermes gateway restart`), so the
chat runs on a profile that can answer. That is an operator decision and does not happen on this
card.
