## Known gaps and deviations (honest list)

1. **Heading.** The card body says "Discover your next world"; `COPY.md` has no id for that string,
   so the binding deck row `discover.title` = "Discover" ships, per the manager ruling of
   2026-11-10 14:06. The surface `h1` is "Workshop" (the destination name); "Discover" is the D2
   head above the tabs.
2. **Banner ground.** The banner composes the featured pack's real cover artifact (1200×800,
   `/media/<artifact>`) beside the paper quiet field, per the same ruling. `CB_ASSETS` deliberately
   excludes shipped scene PNGs, so no media route serves the CP-013 scene itself.
3. **"1 with peek at 460" (card body) vs SPEC-V3.** SPEC-V3 §3.2 fixes compact at "< 620: tab strip,
   single-column rows, mascot hidden" and §3.3 line 150 states "a card grid must not appear at 460
   (rubric §7 dimension 8)". The binding spec wins: at route 460 the surface paints single-column
   rows. There is no horizontal peek shelf. If the owner wants the peek pattern, it needs a spec
   revision first, because the current spec forbids the grid there.
4. **Typographic cover at compact — primitive, not this segment.** With no cover artifact the
   `CoverPlate3` type plate sets the full pack title at `type.heading` with `overflowWrap: 'anywhere'`
   inside an 88 px row plate, so "Parent demo: measuring ingredients together" breaks mid-word as
   "toget her" at route 460. `CoverPlate3` lives in `desktop/src/85-v3-primitives.js` (CP-020b), which
   this card may not edit. Requested primitive change: clamp or step the type plate down by plate
   width (e.g. `lineClamp` + `type.meta` under ~120 px) so no word splits.
5. **Cache reasons for the reviewer.** The five packs' catalog rows ship covers for two packs only;
   the parent demo pack has no cover artifact in the shipped catalogue, so its card is the
   typographic plate by design, and it is the same plate in Store, Library and detail (the named
   test asserts the shared resolver, not that every pack has art).
6. **State frames.** The capture door has no hook for forcing a backend state (loading / empty /
   error / offline / rejected strip), and this card did not add one, so those five states are proven
   by the render harness in `tests/test_cp_021_workshop_v3.py` (skeleton boxes, quiet empty with
   `Import a pack`, error with `Try again`, offline line, rejected strip with `Open Provenance`) and
   not by stamped frames. A reviewer who requires state frames needs a `--state` door hook in a
   CP-020c card; faking them by editing the DOM would not be evidence.
7. **Deferred to CP-040.** The route mount of the six wave surfaces, the `GameHeader` mount-count
   assertion, and the union capture matrix are CP-040's scope; this card captures R-DISC only.
