# [CP-029] GM-015 behavioural probe harness

## Why
GM-015 is the single QA gate and cannot open until every screen lands. Its behavioural list can be turned into runnable probes now, so the gate is execution rather than authoring when the last card merges. This card prepares the instrument only.

## Deliverables (all under `docs/concept-parity/gate/qa/`)
- A runner `probe.py` that takes a built `desktop/plugin.js` (or a running Desktop) and emits PASS/FAIL/SKIP per probe with the command it ran.
- Probes for: keyboard order on the tutor rail and the shelf (tab order asserted, not eyeballed); 200 percent text (no clipping at the card's declared selectors); forced colors (`forced-colors: active`); reduced motion (`prefers-reduced-motion: reduce`); null-runtime render (plugin loads with no host runtime and does not throw); font-load failure; image-load failure; offline; cold profile.
- `README.md` naming each probe, what it asserts, and the exact invocation, plus a `--json` output mode the GM-015 reviewer can attach.

## Rules
- Write only under `docs/concept-parity/gate/qa/`; no plugin, segment, contract or product edits.
- Every probe must be runnable from the repo root and must actually run (no stub that always passes). A probe that cannot be automated honestly is recorded as SKIP with the reason, never as PASS.
- Do not run the gate, do not score any screen, do not claim parity.
