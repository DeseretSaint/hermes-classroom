# [CP-048] Full-window Coursebook surface at reference geometry

Owner `easel`, reviewer `atlas`, 90m, branch `wt/cp-048-window`, skills `coursebook-desktop-rig`, `coursebook-visual-production`.

Why this is blocking parity: the approved references are 1344x768 landscape with Coursebook owning the window. In the current host the plugin renders inside a docked pane whose route measures 341px (chat open) to 744px (wide window) — a different breakpoint and composition from the reference. Measured today: window 1344 -> route 744x714, scope light; chat-open -> 341x608. No amount of polish at 744px can be scored as parity with a 1344px reference.

Do:
1. Add a full-window surface for Coursebook: an action in the plugin (and a deep link the host can open) that opens the coursebook route in its own window at the reference geometry, with no chat sidebar. Use the host API the Desktop already exposes (`window.hermesDesktop.openWindow` / the plugin-window path); do not invent a second app.
2. The window must default to at least 1344x768, remember its size, and render the v3 scope at `data-cb-scope="light"` by default (the approved palette) with a setting to follow the host theme. Dark remains supported, never the default for first run.
3. Keep the docked pane working; it is the compact breakpoint, not the parity surface.
4. Prove it: from the new window, `visual/find-cdp.mjs` -> `node visual/audit.mjs --port <port>` must report route width >= 1344 and scope light, and `scripts/compare-ref.sh` against `docs/concept-parity/refs/home.png` must produce a sheet at the same aspect. Attach the sheet and the measured width.
5. If the host cannot open a plugin window without a core change, stop and report the exact API gap with the call you tried; do not fake a wider pane with CSS zoom.

Done when: the full-window surface exists, measures at reference geometry, defaults to the light palette, and the Home comparison sheet is attached to the review.
